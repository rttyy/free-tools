About this free tool
Clean up noisy analog sensor readings without blindly guessing filter coefficients. This real-time simulator models moving average and low-pass filters directly against simulated ADC noise, displaying phase lag, rise time, and memory overhead side-by-side. Designed for Arduino tinkerers, robotics hobbyists, and embedded engineers.


How to use it
  1. Select your microcontroller architecture (e.g., ATmega328P or ESP32) and enter your sampling rate.
  2. Adjust the target noise reduction slider or input your maximum allowable latency budget in milliseconds.
  3. Compare simulated filter outputs side-by-side to review signal delay, overshoot, and RAM consumption.
  4. Copy the generated, zero-dependency C++ class or Arduino testbench directly into your firmware sketch.


Frequently asked questions
What is an efficient algorithm or data structure to calculate moving averages on an MCU?
For a standard simple moving average (SMA), use a circular ring buffer with a running sum. Instead of iterating through the entire window every cycle, subtract the oldest value falling out of the window, add the new reading, and divide the sum by the window length. For even lower memory and zero array overhead, use an Exponential Moving Average (EMA), which stores only a single filtered value in RAM and updates via a single multiply-accumulate operation.
How do you read a varying voltage cleanly into an Arduino?
To read varying voltages accurately, first decouple the hardware line with a 100nF ceramic capacitor between the analog pin and GND close to the board. Second, ensure your input impedance is under 10k ohms to let the ADC sample-and-hold capacitor charge fully. In firmware, take a dummy read after switching ADC channels, discard it, and run subsequent samples through a software low-pass or moving average filter.
What are the different (and fastest) ways to compute sines and cosines in Arduino?
The default `sin()` and `cos()` functions in the standard AVR library use double-precision floating-point software emulation, taking upwards of 120 microseconds on an 8-bit ATmega328P. The fastest approach is an integer lookup table (LUT) stored in flash memory (`PROGMEM`) combined with linear interpolation, taking under 2 microseconds. A secondary approach is a 16-bit fixed-point CORDIC routine or Taylor series approximation if RAM/flash is strictly constrained.
